# v1.1.6 read-only user bridge

The v1.1.6 user bridge is a closed, read-only boundary for projections that
remain owned by the `god` user. It does not grant the dedicated `overseer`
principal access to the Codex home, Codex credentials, prompts, environment,
tmux, shell commands, or user-owned databases.

## Contract

The root-created system socket is:

```text
/run/overseer/codex-user-bridge.sock
```

The socket is owned by `god`, shared only with the `overseer` group, and the
bridge verifies Linux `SO_PEERCRED` against the configured numeric `overseer`
UID. A peer cannot assert its own identity in the request body.

Requests are newline-delimited JSON with exactly these fields:

```json
{
  "protocol": "overseer.user-bridge.v1",
  "request_id": "bounded-id",
  "method": "codex.sessions.list.v1",
  "params": {}
}
```

Only these methods exist in this version:

- `codex.sessions.list.v1`
- `codex.usage.snapshot.v1`

Both methods require an empty `params` object. Unknown fields, mutation-like
parameters, paths, shell text, environment values, credentials, prompts, and
tmux targets are rejected. Requests and responses have hard size bounds;
projection lists are separately bounded and only allowlisted redacted fields
are returned.

Each projection reports an explicit `available`, `stale`, `unavailable`, or
`error` state. Provider exceptions and timeouts become generic redacted error
states. Reusing a request ID with the same request is idempotent; reusing it
with different bytes is rejected.

Projection providers are injected into `UserBridge`; the socket-activated
entry point wires the fixed read-only providers for `/home/god/.codex/codex-projects.csv`
and `/home/god/.local/share/overseer/codex-usage-mcp/state.sqlite3`. Those
providers never write their sources. Session and project identifiers are
hashed, and usage windows are reduced to bounded, non-account fields. The
bridge module does not import Codex, tmux, shell, network, or credential
integrations.

The service receives a tmpfs view of the user home with only the exact Codex
registry file and Codex Usage state directory bound read-only. Codex login
material, rollout transcripts, tmux state, and the rest of the home directory
are absent from its mount namespace. Network access is disabled.

The `UserBridgeClient` checks the socket's owner, type, mode, and inode before
and after connecting, then verifies the connected server's `SO_PEERCRED` UID.
The server independently verifies the connecting `overseer` UID. Client I/O
is one bounded newline-delimited request and one bounded newline-delimited
response; missing, malformed, oversized, trailing, or timed-out frames fail
closed.

## Activation boundary

`systemd/overseer-tmpfiles.conf`,
`systemd/overseer-codex-user-bridge.socket`, and
`systemd/overseer-codex-user-bridge.service` are source templates only. They
are not installed, enabled, started, or otherwise activated by this change.
The `@OVERSEER_UID@`, `@OVERSEER_RELEASE@`, and `@OVERSEER_PYTHON@`
placeholders must be resolved by the separately approved activation process.
